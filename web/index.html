Built for evidence, not a fake control room.

The web portal explains the same defensive operating model used by the terminal workstation and local monitoring stack.

01 / INGEST

Schema-driven evidence intake

One or many supported files can be supplied. AquaSentinel profiles the actual structure and does not require a fixed filename or sensor list.

02 / AI

Adaptive anomaly analysis

Usable numeric features are discovered automatically. Sufficient data can use Isolation Forest while smaller datasets use robust statistical fallback.

03 / ASSURANCE

Provenance and reporting

SHA-256 fingerprints, missingness, time evidence, domain confidence and analysis limitations are preserved for human review.

04 / WATER

Water-quality evidence

Fields such as pH, turbidity, conductivity or chlorine are treated as semantic clues when present—not mandatory assumptions.

05 / OT

OT and SCADA evidence

Operational and security observations can be analyzed offline without connecting to live PLCs, plant networks or industrial devices.

06 / MONITOR

Prometheus + Grafana

The active evidence package can publish local metrics for visualization while the analysis engine remains read-only.

Analysis path

Every stage is derived from operator-supplied evidence. Missing evidence does not become a synthetic result.

Safety boundary

Designed to advise, never actuate.

AquaSentinel does not connect to or control PLCs, SCADA systems, pumps, valves, dosing controllers, treatment equipment or water utilities. An anomaly is not proof of contamination, unsafe water or cyber compromise.
